# Zitch mobile audit — 17 October 2026

Release target: standard Zitch 1.0.8, Android version code 16, with WhatsApp retained. Base commit: `12a1001b3066532157be431bd7579ab268336d4b`.

## Scope and conclusion

All 59 screen files and four navigation layouts were inspected individually. Concrete UI, recovery, payment review, account-switch and asynchronous-action defects were repaired. This is an application quality and safety update; it does not certify live settlement or enable unavailable financial products.

The core changes preserve kobo during amount entry, bind PIN authorization to reviewed details, reject stale results after account changes, protect WhatsApp approval tokens from replacement races, expose loading/error/retry states, and make navigation, contrast, touch targets and long text consistent. Missing limits remain unconfirmed rather than becoming zero. Financial holds and durable retry protections remain enforced.

## Verification

- Integrated mobile suite: **72 suites, 783 tests and one snapshot passed**.
- TypeScript and repository ESLint: passed. Build-tool compatibility: **30 tests passed**.
- All 59 routes rendered at 390px and 320px with synthetic fixture data, including protected-route recovery and unavailable-service states. No document-level horizontal overflow. Browser observations are not native-device or live-bank evidence.
- Browser QR scanning is intentionally unavailable in the app; its native camera path is tested with mocks. The isolated browser also blocked the Expo camera dependency's external QR worker.
- Four primary tabs, WhatsApp entry, decimal amount review, PIN choice/close, dark-mode switch and all onboarding slides were exercised in the browser. Sixteen representative routes also rendered in dark mode at 1024px with no document-level overflow.
- The Android release workflow independently validates package/version/security/signature and emulator startup/recovery. Its smoke test does not cover authenticated banking.

## External acceptance gates

Provider configuration health and published WhatsApp Flow status are separate from a completed customer journey. Outstanding acceptance gates include historical funding/reconciliation reviews, pool-balance query failure, Tier 2 interactive identity-provider integration, Tier 3 completion evidence, Mono callback-contract verification, native push configuration/delivery, physical-device biometrics and a controlled end-to-end banking journey. A successful application build does not close these gates. No live customer transaction or outbound message was used for this audit.

The release is an internal test-key-signed Android prerelease, not a Play Store production approval. Use the exact release tag and checksum rather than the repository's generic latest-release redirect.
